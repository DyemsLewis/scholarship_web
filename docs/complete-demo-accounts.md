## Reusable Applicants

Each verified applicant has applications in multiple scholarships. Open Applications or Scholarship Support and choose the program, rather than signing into a different applicant for every stage.

| Applicant | Processes available on the same account |
| --- | --- |
| `learner.aurora` | Pre-screening, completed exam awaiting outcome/evaluation, completed interview awaiting outcome/evaluation, final DSS comparison, agreement acceptance, benefit receipt confirmation, one-time release planning, and applying to the open grant |
| `learner.brio` | Formal application, exam assignment, online interview acknowledgment, final DSS comparison, first release planning, renewal/completion after settled benefits, and one-time distribution recording |
| `learner.cielo` | Exam acknowledgment, interview assignment, final DSS comparison, original-document check-in review, an upcoming check-in with map, and one-time receipt confirmation |
| `learner.dune` | Exam session completion, a missing interview evaluation before final comparison, closing a fully reviewed check-in, e-wallet destination review, and completing a received one-time award |
| `learner.profile` | Complete the profile and upload supporting evidence before verification |
| `learner.verification` | Submitted profile evidence ready for the admin review officer to review |

The four reusable applicants have verified profiles. Scholarships in this dataset allow other scholarship support so parallel records do not contradict their eligibility policies. No failed/rejected outcomes are pre-recorded. Current decisions are left to the tester; selected outcomes exist only where needed to demonstrate later support actions.

## Suggested Order

1. Use `lumenops.reviews` with `learner.verification` for profile evidence and final profile verification.
2. Use `orivanta.programs` for the draft, then `lumenops.reviews` for the pending program.
3. Use `learner.aurora` to browse and start an application to the open grant.
4. Use `orivanta.reviewer`, `orivanta.selection`, and `orivanta.decisions` for the prepared selection records. Switch among the four applicant accounts only when demonstrating an applicant-owned action.
5. Use `learner.aurora` for agreement acceptance, then `orivanta.releases` for first-release planning.
6. Use `orivanta.monitoring` and `orivanta.recipients` for original-document checks, case closure, and support renewal/completion.
7. Use `orivanta.releases` and the applicant accounts for payment-details review, distribution evidence and receipt confirmation.
8. Use the one-time award to demonstrate its shorter completion process.
9. Show support and optional services, followed by manager and super-admin overviews.
